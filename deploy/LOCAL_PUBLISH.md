# 本地每分钟检查，有变化才发布

电脑保持开机联网，本地每 60 秒同步公开原表，检查场次、判断、赛果及预测留档差异；有实际变化才提交并推送 `main`，由现有 GitHub Actions 发布到 Pages。只有 `fetchedAt` 改变时不提交、不发布，不需要云服务器。

## 启动

先确保本次网页代码已按正常流程发布一次，并能在当前电脑向仓库推送。服务读取当前仓库 `origin`，使用专用 `.local-publisher/` Git 副本，不把开发目录中的代码修改混入数据提交。

```bash
npm ci
npx playwright install chromium
npm run publish:watch
```

首次立即检查，此后每分钟检查，未结束的任务不会重叠。按 `Ctrl+C` 停止。仅检查一次可执行 `npm run publish:watch -- --once`。

`PUBLISH_WORKDIR` 可指定专用副本目录，`PUBLISH_BRANCH` 默认 `main`；`PUBLISH_INTERVAL_MINUTES` 默认 `1`。副本不能与当前开发目录相同，锁文件防止重复启动。

## 发布行为

- 拉取远端更新后同步数据，只有两个数据文件参与自动提交。
- 比较数据时忽略抓取时间，JSON 属性顺序变化也不触发发布。
- 首次预测记录与新赛果属于实际变化，会保留并发布；推送失败后下轮重试，不覆盖已有预测方向。
- Git 合并冲突或认证失败时保留线上旧版本，日志提示失败；修复发布副本或推送权限后再运行。
- Pages 有构建、发布及缓存延迟，一分钟是检查频率，不承诺变更恰好一分钟内上线。查看 Actions 确认发布完成。

网页每分钟检查已发布快照。没有新数据时，线上同步时间仍是最近一次发布的真实抓取时间，不会人为每分钟改成当前时间。

使用此方案时，仓库变量 `DATA_API_URL` 应保持未设置，让网页读取 Pages 自身的 `data-snapshot.json`。如已连接独立数据服务，可继续使用该服务；两种方案选其一即可。
