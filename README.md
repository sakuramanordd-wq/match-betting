# 平安京 · 对弈数据

阴阳师非官方社区数据看板，优先展示当前活动最近场次，支持按活动、日期查看历史结果与各方判断。首屏依次展示本场红蓝人数比例、历史评估加权比例和每位记录者的选择、原表胜场/败场/胜率/总场次及本场前评估分；人数比例与加权比例上下展示，点击「查看详细计算」在弹窗中查看公式、统计口径、本场代入数值、历史回放指标和实际留档成绩；下方切换查看其他场次。移除模拟竞猜、虚拟勾玉和结算功能。

数据来源：[2026国庆对弈竞猜汇总（尽量准时版](https://www.kdocs.cn/l/cris3KItpMwO)。当前收录 2026 国庆、2026 春节、2025 国庆、2025 春节，共 196 个排期。本站显示静态快照，页面标明同步时间；不接入游戏实时接口，空白不推断赛果，人数比例和加权比例不代表获胜概率。胜场、败场、胜率、总场次直接同步原表累计统计，可能包含当前或之后场次；展示保留原表文本，空白不推断为零。用于评估的历史命中率使用所有已收录活动中、本场之前已知赛果，记录者按原表名字精确匹配；评估分 =（历史命中 + 2）÷（有效样本 + 4）× 100，用平滑处理降低小样本的极端影响，无历史为 50 分。加权比例 = 该方评估分总和 ÷ 全部评估分总和；无判断时不显示百分比。

## 预测与验证

独立「风向预测」框来自 [对弈竞猜实时风向](https://yysrank.com/dyjc.html)，按原站口径统计北京时间最近偶数整点之后发布的博主预测，展示明确红蓝方向的条数、比例和博主明细。它展示当前时段风向，不随历史场次筛选切换，不参与历史评估加权，也不是获胜概率。原站标注约每20分钟更新；本地每分钟监控同时抓取该来源，保存在 `match-data.json` 的 `wind` 字段，实际内容变化才发布，时间变化不会单独触发发布。线上读取已发布快照，存在 Actions 发布延迟；抓取失败保留旧快照并提示。新增功能代码需先正常部署一次，数据监控才能更新线上此框。

固定规则：以每位记录者的本场前评估分作为权重，红方加权比例超过 50% 则倾向红方，低于 50% 则倾向蓝方；持平或没有本场判断时不预测。跨活动仅匹配完全相同的名字，不自动合并别名。历史回放按场次时间逐场重建，只用更早场次的结果，并展示有效场次、跳过场次、命中率及与多数判断的同样本比较，不将判断占比当作获胜概率。

旧表没有历史判断的填写时间，也没有赛果发布时间，不能证明历史记录都是事前判断；回放仅验证当前快照下的规则表现。`npm run sync:data` 会自动为有判断且尚无赛果的场次保存首次预测至 `forecast-history.json`，后续同步只更新验证结果，保留原方向、生成时间与模型版本。历史回放成绩与首次留档预测成绩分开展示，已知赛果不补造预测留档。首次观察到的判断持平时保留“暂不预测”，不计入命中率。

```bash
npm run sync:data             # 更新快照，生成/验证新场次的首次预测
npm run evaluate:predictions  # 查看回放及实际留档评估报告
```

通过本地启动脚本运行时，每分钟自动同步原表并生成/验证预测，页面每分钟读取最新快照，无需手动刷新。页面打开详情弹窗时暂缓更新，关闭后检查更新；同步失败保留旧数据及真实同步时间。GitHub Pages 可通过独立数据服务每分钟获取最新数据；配置仓库变量 `DATA_API_URL` 为服务的 HTTPS 快照接口即可，详见 [线上数据服务部署](./deploy/DATA_SERVICE.md)。未配置服务时仅每分钟检查发布快照。同步完成但没有本场判断时仍不生成预测。

## 本地自动发布（无需云服务器）

运行 `npm run publish:watch`，每分钟同步并检查数据，有实际变化才推送并触发 Pages 发布；仅抓取时间变化时跳过。使用独立 Git 副本，不混入开发修改。运行日志追加至 `.local-publisher.log`，可用 `tail -f .local-publisher.log` 查看每轮同步、推送或跳过及失败阶段。电脑需保持开机联网并具有 Git 推送权限，详细说明见 [本地自动发布](./deploy/LOCAL_PUBLISH.md)。网页每分钟读取已发布快照，实际上线时间还包含 Actions 发布延迟。


每轮还会记录北京时间当前场次（最新已开始排期）的预测人数：线上已发布快照与本轮最新抓取分别列出总人数、红蓝人数、人数差额、判断内容是否一致及各自真实抓取时间。双方比较同一个活动和场次；线上读取失败或缺失该场次时标为未知，不当作零人，部署失败或排队时也继续比较。

每轮无论数据是否变化，都会只读检查当前提交对应的 Pages 工作流，并核对线上快照内容（忽略抓取时间，包含预测留档）。日志区分数据推送、发布排队/执行中、部署失败、快照尚未更新、已核验上线及查询失败；推送不代表上线。`--once` 遇到部署失败或无法查询时返回非零退出码。

修复失败原因后，可在 Actions 点击 **Re-run all jobs** 重跑已有提交；或安装并登录 GitHub CLI 后执行 `npm run publish:watch -- --once --retry-deploy`。此参数仅重跑已确认失败的当前提交流程，不制造数据提交，每个失败流程在同一进程中最多重试一次，避免对确定性测试错误反复重跑。认证由 `gh` 管理，脚本不读取或保存凭据。

## 开发与同步

### 本地一键启动

安装 Node.js 24 后，在 Bash 环境（Linux、macOS 或 Windows Git Bash / WSL）执行：

```bash
./scripts/local-deploy.sh          # 安装依赖并启动热更新，http://127.0.0.1:5173
./scripts/local-deploy.sh preview  # 安装依赖、生产构建并预览，http://127.0.0.1:4173
```

脚本可从任意目录调用，按 `Ctrl+C` 停止。每次运行通过 `npm ci` 安装锁定依赖，需要能访问 npm 源。端口占用时会报错，可用 `PORT=5174 ./scripts/local-deploy.sh` 指定其他端口；手机同一局域网调试可用 `HOST=0.0.0.0 ./scripts/local-deploy.sh`，再访问电脑的局域网 IP 和端口。脚本默认开启每分钟原表同步，并自动安装同步所需的 Chromium；首次同步完成前展示现有快照。`LOCAL_AUTO_SYNC=0 ./scripts/local-deploy.sh` 可关闭自动同步。普通 `npm run dev` / `npm run preview` 默认仅检查已有快照，使用 `LOCAL_AUTO_SYNC=1` 可开启原表同步。

Node.js 24，执行：

```bash
npm ci
npx playwright install chromium
npm run dev
# 从公开文档只读提取，更新 match-data.json
npm run sync:data
npm test
npm run build
npm run preview
```

同步失败会保留原快照。同步脚本使用公开访客视图，不需要账号、密钥，不修改原文档。同步后检查差异、测试和构建，再随代码发布；访问网页不会自动请求金山文档。原表结构改变时更新脚本映射，勿将记录者的判断当作结果。

测试检查数据格式、当前时段、历史活动和日期切换、未知结果、详情弹窗与焦点、旧存档保留、390px/1440px 布局，并使用生产子路径 `/match-betting/`。
